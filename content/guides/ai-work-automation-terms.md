"AI로 고객 문의 처리를 자동화해 보자"는 말에는 여러 선택이 숨어 있어요. 정해진 절차를 따르게 할지, 상황에 따라 행동을 고르게 할지, 회사 시스템에는 어떻게 연결할지 정해야 하죠. 문의를 분류하고 자료를 찾아 답변 초안을 만드는 예시로 아래 5개를 연결해 볼게요.

## 1. AI 워크플로우란 무엇일까요?

AI와 일반 프로그램, 사람의 작업을 미리 정한 단계와 조건으로 연결한 업무 흐름이에요. 접수, 분류, 자료 조회와 검토처럼 각 단계의 입력과 출력을 정해요. 조건 분기와 반복도 가능해요.

> **쉽게 비유하면**
>
> 접수 창구에서 검토 담당자를 거쳐 승인자에게 가는 업무 절차에 AI 담당 단계를 넣는 것과 같아요.

**예를 들면** AI가 문의를 분류하고, 긴급 건은 담당자에게 보내며, 일반 건은 초안을 만들어 검토 대기함에 넣어요.

**회의에서는 이렇게** "단계마다 완료 기준과 실패했을 때의 재처리·인계 경로부터 정하죠."

## 2. AI 에이전트란 무엇일까요?

목표를 이루기 위해 다음 행동을 고르고, 도구를 사용하며 결과에 따라 진행하는 시스템이에요. 워크플로우가 정해진 흐름을 중심으로 한다면 에이전트는 상황에 따른 행동 선택이 중심이에요. 실제 구성에서는 둘을 섞을 수 있어요.

> **쉽게 비유하면**
>
> 체크리스트대로만 움직이는 절차와 달리, 조사 결과를 보고 다음에 누구에게 무엇을 확인할지 고르는 업무 담당자와 비슷해요.

**예를 들면** 에이전트가 문의를 읽고 규정 검색이 필요한지, 주문 상태 조회가 필요한지 골라 확인한 뒤 초안을 작성해요. 어디까지 실행할 수 있는지는 도구와 권한 설정에 달려 있어요.

**회의에서는 이렇게** "조회와 초안 작성까지 맡기고, 환불 실행과 외부 발송에는 담당자 확인을 두죠."

## 3. 함수 호출이란 무엇일까요?

모델이 외부 기능을 쓰기 위해 함수 이름과 입력값을 정해진 형식으로 요청하는 방식이에요. 모델이 호출 정보를 만들고, 앱이나 실행 환경이 권한과 값을 검증한 뒤 실제 도구를 실행해요.

> **쉽게 비유하면**
>
> "주문 좀 알아봐 주세요"라고 자유롭게 말하는 대신, 주문 번호를 적은 정해진 조회 신청서를 보내는 것과 같아요.

**예를 들면** 모델이 주문 조회 함수와 주문 번호를 요청하면 서버가 조회 권한을 확인하고 결과를 돌려줘요. 모델이 번호를 만들었다고 그대로 믿어서는 안 돼요.

**회의에서는 이렇게** "도구 입력과 사용자 권한은 서버에서 검증하고, 조회 실패도 구분해서 모델에 돌려주죠."

## 4. MCP란 무엇일까요?

Model Context Protocol의 줄임말로, AI 앱이 외부 도구와 자료에 연결되는 방식을 공통화하는 공개 프로토콜이에요. 서버가 도구와 리소스 등을 제공하고 앱의 클라이언트가 연결해 사용해요.

> **쉽게 비유하면**
>
> 기기마다 전용 연결선을 만드는 대신 공통 규격의 단자를 쓰는 것과 비슷해요.

**예를 들면** 사내 규정 검색을 MCP 서버로 제공하면, 지원하는 AI 앱이 정해진 방식으로 기능을 발견하고 요청할 수 있어요. 연결이 공통화돼도 접근 권한과 실제 검색 품질은 따로 관리해야 해요.

**회의에서는 이렇게** "MCP로 연결하되, 사용자가 볼 수 있는 문서만 검색 결과로 반환하게 하죠."

MCP의 범위와 구성 요소는 [공식 아키텍처 문서](https://modelcontextprotocol.io/docs/learn/architecture)를 참고했어요. 함수 호출은 모델이 실행을 요청하는 방식이고, MCP는 외부 기능과 연결하는 규격이라는 차이가 있어요.

## 5. 모델 평가란 무엇일까요?

AI 모델이나 전체 시스템이 목적에 맞게 작동하는지 기준과 사례로 확인하는 과정이에요. 자동화에서는 답변 문장뿐 아니라 도구 선택, 잘못된 실행, 사람에게 넘겨야 할 상황의 처리도 확인해요.

> **쉽게 비유하면**
>
> 업무 교육을 마친 뒤 필기 답안뿐 아니라 실제 처리 과정과 예외 상황 대응까지 확인하는 실습 평가예요.

**예를 들면** 일반 문의, 주문 번호 누락, 권한 없는 조회와 시스템 장애 사례를 준비해 기대한 경로로 처리되는지 봐요. 비용, 응답 시간과 담당자 수정량도 함께 비교할 수 있어요.

**회의에서는 이렇게** "시연이 잘된 몇 건뿐 아니라 실제 문의와 어려운 사례로, 변경 전후의 성공·실패를 비교하죠."

## 자동화 설계에 연결하기

| 설계 질문 | 관련 용어 |
| --- | --- |
| 절차와 분기, 담당자 확인은 어떻게 연결하나요? | AI 워크플로우 |
| 어떤 행동을 상황에 따라 선택하게 하나요? | AI 에이전트 |
| 외부 기능을 어떤 입력으로 요청하나요? | 함수 호출 |
| 외부 도구와 자료를 어떤 공통 규격으로 연결하나요? | MCP |
| 실제로 잘 처리했는지 어떻게 확인하나요? | 모델 평가 |

우선 자동화할 업무 한 가지를 정해 **입력, 허용된 행동, 완료 기준과 사람에게 넘길 조건**을 적어 보세요. 그다음 어떤 단계에 AI의 판단이 필요한지 정하면 도구 선택도 구체화돼요.
