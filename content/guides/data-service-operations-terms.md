대시보드가 잘 열린다고 데이터 서비스가 정상인 것은 아니에요. 어제 자료가 아직 안 들어왔거나, 같은 주문이 두 번 쌓였거나, 부서마다 매출을 다르게 계산하고 있을 수 있어요. 아래 10개 용어를 알면 데이터의 수집·처리·활용 과정에서 어디를 확인하고 누구와 합의해야 할지 보이기 시작해요.

## 1. 데이터베이스란 무엇일까요?

데이터를 체계적으로 저장하고 조회·변경할 수 있게 조직한 모음이에요. 관리 시스템이 접근과 변경을 처리해요. 운영에서는 어떤 곳의 기록을 기준으로 삼는지, 여러 시스템의 값이 다르면 무엇을 확인할지 정해야 해요.

> **쉽게 비유하면**
>
> 여러 사람이 함께 쓰는 업무 장부예요. 어느 장부가 원본인지 알아야 숫자가 다를 때 추적할 수 있어요.

**예를 들면** 주문 상태는 주문 시스템, 환불 확정은 결제 시스템에서 관리할 수 있어요. 분석에는 두 기록을 어떤 시점으로 연결할지 정해야 해요.

**회의에서는 이렇게** "이 지표의 원천 시스템과 기준 시점을 먼저 확인하죠."

## 2. 데이터 파이프라인이란 무엇일까요?

데이터의 수집, 처리와 전달을 여러 작업으로 연결한 체계예요. 정해진 시간에 묶어서 처리하거나 이벤트를 계속 처리할 수 있어요. 단계별 성공 여부뿐 아니라 최종 데이터가 언제까지 반영됐는지 확인해야 해요.

> **쉽게 비유하면**
>
> 재료가 여러 공정을 통과하는 생산 라인이에요. 마지막 기계가 돌아가도 앞 공정에서 재료가 빠졌다면 완제품이 부족해요.

**예를 들면** 주문 수집은 성공했지만 분석 테이블 갱신이 실패하면 화면은 열려도 어제 숫자가 남을 수 있어요.

**회의에서는 이렇게** "작업 성공 시각과 데이터가 실제 반영된 마지막 시각을 구분해 보여 주세요."

## 3. ETL이란 무엇일까요?

데이터를 추출하고, 목적에 맞게 변환한 뒤, 대상에 적재하는 과정이에요. 파이프라인의 한 방식이며 모든 파이프라인이 ETL 순서를 따르지는 않아요. 운영에서는 실패 후 재실행해도 결과가 중복되지 않는지 중요해요.

> **쉽게 비유하면**
>
> 재료를 가져와 손질한 뒤 납품하는 과정이에요. 배송을 다시 했다고 같은 주문을 두 번 납품하면 안 되겠죠.

**예를 들면** 중간 실패 후 하루치 주문을 다시 넣더라도 주문 식별자를 기준으로 기존 기록과 새 기록을 올바르게 처리해야 해요.

**회의에서는 이렇게** "재실행 시 중복과 누락이 생기지 않는지, 원천과 적재 건수도 맞춰 보죠."

## 4. 데이터 전처리란 무엇일까요?

데이터를 사용하기 전에 중복, 누락과 형식을 점검하고 목적에 맞게 정리하는 과정이에요. 원본과 처리 규칙을 남겨야 결과를 설명하고 다시 만들 수 있어요. 이상해 보이는 값을 무조건 지우는 것은 아니에요.

> **쉽게 비유하면**
>
> 재료를 손질하되 무엇을 왜 덜어 냈는지 기록하는 일이에요. 특이한 재료가 꼭 상한 재료는 아니에요.

**예를 들면** 금액이 비어 있는 주문을 0원으로 채우면 미확정 주문이 무료 주문처럼 집계될 수 있어요.

**회의에서는 이렇게** "누락값의 업무 의미를 확인한 뒤 처리하고, 바뀐 건수와 규칙을 기록하죠."

## 5. 메타데이터란 무엇일까요?

데이터의 뜻, 출처, 형식과 관리 상태를 설명하는 정보예요. 단위와 계산 기준, 담당자와 갱신 시각이 여기에 포함될 수 있어요. 데이터가 어떤 변환을 거쳤는지 나타내는 계보도 원인 추적에 도움이 돼요.

> **쉽게 비유하면**
>
> 식품의 원산지, 성분과 유통 정보를 적은 라벨이에요. 내용물만 보고는 알기 어려운 맥락을 알려 줘요.

**예를 들면** 매출 1,000이 원인지 천 원인지, 세금과 환불을 포함하는지 설명이 없으면 잘못 읽을 수 있어요.

**회의에서는 이렇게** "단위와 정의, 담당자, 갱신 주기를 데이터 설명에 함께 남겨 주세요."

## 6. 데이터 웨어하우스란 무엇일까요?

여러 시스템의 데이터를 공통 기준으로 정리해 분석과 보고에 활용하는 저장·분석 체계예요. 실시간 주문 처리용 데이터베이스와 목적이 달라요. 자료가 모였다고 최신성과 정확성이 저절로 보장되지는 않아요.

> **쉽게 비유하면**
>
> 부서별 장부를 같은 기준으로 맞춰 모아 둔 경영 분석실이에요.

**예를 들면** 온라인과 매장 매출을 통합하면서 판매일, 취소일과 환불일 중 어떤 날짜를 기준으로 볼지 맞춰요.

**회의에서는 이렇게** "통합 매출의 계산 기준과 갱신 지연을 문서화하고 원천 합계와 대조하죠."

## 7. 데이터 카탈로그란 무엇일까요?

어떤 데이터가 어디 있고 어떻게 사용해야 하는지 찾는 목록과 탐색 체계예요. 메타데이터를 모아 설명과 담당자, 품질 상태 등을 확인하게 해요. 목록에 있다고 모든 사람이 접근할 수 있는 것은 아니에요.

> **쉽게 비유하면**
>
> 책의 위치, 설명과 대출 조건을 알려 주는 도서관 검색 목록이에요.

**예를 들면** 매출 테이블이 여럿일 때 어떤 것이 공식 보고용인지와 담당자를 찾아 확인할 수 있어요.

**회의에서는 이렇게** "새 테이블을 만들기 전에 기존 자산을 찾고, 폐기한 테이블은 상태를 표시하죠."

## 8. 데이터 거버넌스란 무엇일까요?

데이터를 관리하고 활용할 역할, 기준과 의사결정 절차를 정하는 체계예요. 품질 문제의 책임자, 지표 정의의 승인자와 변경 절차 등을 정해요. 도구 하나를 설치하는 것만으로 완성되지 않아요.

> **쉽게 비유하면**
>
> 공용 자료실의 이용 규칙과 관리 책임, 분쟁이 생겼을 때 결정할 절차를 마련하는 일이에요.

**예를 들면** 활성 고객의 정의가 달라졌을 때 누가 승인하고 과거 지표를 다시 계산할지 결정해요.

**회의에서는 이렇게** "이 데이터의 업무 책임자와 오류 대응 담당자, 정의 변경 절차를 정하죠."

## 9. 개인정보란 무엇일까요?

살아 있는 개인을 알아볼 수 있거나 다른 정보와 쉽게 결합해 알아볼 수 있는 정보예요. 이름뿐 아니라 식별자와 행동 기록도 맥락에 따라 해당할 수 있어요. 가명처리와 익명화도 같은 의미가 아니에요.

> **쉽게 비유하면**
>
> 이름표를 떼어도 여러 단서를 조합하면 주인을 알아볼 수 있는 물건과 같아요.

**예를 들면** 이름이 없는 주문 기록도 회원 번호와 주소 등을 연결하면 개인을 알아볼 수 있어요. 분석 목적에 필요한 항목과 접근 범위를 정해야 해요.

**회의에서는 이렇게** "이름을 지웠다는 이유만으로 공유하지 말고, 결합 가능성과 보관·삭제 범위를 확인하죠."

개념과 가명정보의 범위는 [개인정보 포털의 공식 설명](https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=27)을 참고했어요.

## 10. 비즈니스 인텔리전스, BI란 무엇일까요?

업무 데이터를 분석하고 보고해 의사결정을 돕는 활동과 시스템이에요. 대시보드 화면뿐 아니라 데이터 연결과 지표 정의, 보고 과정도 포함돼요. 차트가 정상 표시되는지와 숫자가 올바른지는 따로 확인해야 해요.

> **쉽게 비유하면**
>
> 조직의 계기판이에요. 화면에 숫자가 켜져 있어도 센서나 계산 기준이 틀리면 잘못 판단할 수 있어요.

**예를 들면** 매출이 급감하면 실제 판매 변화인지, 적재 실패인지, 계산식 변경인지 나눠 조사해요.

**회의에서는 이렇게** "지표와 함께 데이터 기준 시각을 표시하고, 이상 수치의 원천까지 따라갈 수 있게 하죠."

## 운영 점검에 연결하기

| 확인할 문제 | 살펴볼 개념 |
| --- | --- |
| 늦게 오거나 중복된 데이터 | 데이터베이스, 데이터 파이프라인, ETL |
| 값이 바뀌거나 뜻을 모르는 데이터 | 데이터 전처리, 메타데이터 |
| 같은 지표인데 숫자가 다름 | 데이터 웨어하우스, BI |
| 어디 있는지, 누구에게 물을지 모름 | 데이터 카탈로그, 데이터 거버넌스 |
| 필요한 범위를 넘는 노출과 보관 | 개인정보 |

운영 기준에는 **최신성, 누락·중복, 정의와 책임자**를 함께 담아 보세요. 문제가 생겼을 때 "화면이 이상하다"에서 멈추지 않고 조사할 지점을 찾을 수 있어요.
